How should the flow graph be drawn?

Same endpoint (POST /entity/financials, crossing 4 repos). Three ways to render it. Your goal is "see integration between repos", so where service boundaries show up is the key difference. Click to select.

A

Cross-repo swimlanes  (recommended)

One lane per repo/service. The request flows left→right and every time an arrow crosses a lane boundary, that's an integration point — exactly what you want to see. Hops between repos are visually obvious.

→ each lane crossing = an integration boundary ←
B

Linear call chain

Simple top-to-bottom list of steps with the repo named on each node. Compact and easy to read for short flows, but cross-repo boundaries are just a label, not spatially obvious.

edfx-app-ui · FinancialsView.tsx
↓
edfx-api · /v2/financials
↓

↓
client-financials-api · getFinancials()
C

Sequence diagram (lifelines)

UML-style: each repo is a vertical lifeline, messages are horizontal arrows with request/response. Great for request/response detail and timing, but denser to read at a glance. (We can still generate this as an export — req 3e — regardless of the in-dashboard choice.)

app-ui →→ edfx-api : POST /v2/financials  |  edfx-api →→ entity-api : resolve  |  entity-api ⇠ returns id

My lean: A (swimlanes) in the dashboard because it makes repo integration boundaries the visual star, plus generate C (sequence) on demand as an export artifact. But pick what reads best to you.
